Parse `$ARGUMENTS` for `--review-with <entry[,entry,...]>`. This is the one definition of the reviewer grammar; the multi-reviewer loop takes the entries as parsed here.

```
entry := ( <agent> [ "[" <model> "]" ] | "cmd[" <invocation> "]" | "@" <login> ) ( "~opt" | "~max=" <n> | "~effort=" <level> )*
```

- **Reserved value `none`** (case-insensitive) is not a slug: `--review-with none` means no external reviewer this run. Set `REVIEW_AGENTS=[]`, skip the parsing below, and skip any saved `review-with` default.
- **Split** the value on `,` outside the outermost brackets and trim whitespace. "Outermost" is the first `[` to the last `]` of a token, so a `,` or `~` inside `cmd[…]` or a nested model (`cursor[claude-opus-4-7[thinking=true,effort=high]]`) is part of the value.
- **Suffixes** come off the right of each token, after its last `]`, in any order and at most one of each, before the rest is parsed (`cmd[a]~opt[b]` is the invocation `a]~opt[b` with no suffix). None is part of the dedup identity.
  - `~opt` sets `{OPTIONAL}` (default `false`). The reviewer still runs and its findings are still fixed, but an inconclusive result (timeout, skipped, incomplete, no verdict) does not block this command's merge. A hard error (broken build, failed tests, rejected fixes) or unpushed fixes still block.
  - `~max=<n>` sets `{ENTRY_MAX}`: that reviewer's cap on review → fix → re-review cycles, a non-negative integer. It applies to every reviewer type, so one call can budget each: `--review-with claude~max=2,ollama~max=1,codex~max=3`. `0` means "loop until clean", bounded by the loop's built-in ceiling of 10 rounds.
  - `~effort=<level>` sets `{ENTRY_EFFORT}`: `low`, `medium`, `high`, `xhigh`, or `max`.
  - Reject a malformed, repeated, or unknown suffix with `Invalid --review-with suffix on {entry}: ~max must be a non-negative integer and ~effort must be one of low, medium, high, xhigh, max, each appearing at most once; the only suffixes are ~opt, ~max=<n>, and ~effort=<level>.`
- **Agents**: `codex`, `agy` (aliases `gemini`, `antigravity`), `claude`, `grok`, `pi`, `cursor` (alias `cursor-agent`), `opencode` (aliases `zen`, `opencode-zen`), `ollama`, and `copilot` (GitHub's cloud Copilot review; legacy, supported when named, never selected implicitly, and recorded `skipped` on any other host). Normalize aliases to the base slug.
- **`[<model>]`** is accepted by every agent except `copilot` (`copilot[…]` gets the unknown-value abort). The value is everything between the outermost brackets, free-form (spaces and parentheses allowed, e.g. `codex[o3]`, `opencode[provider/model]`, `ollama[qwen2.5-coder:32b]`); validate its shape, not an allowlist. Record it as the entry's `REVIEW_MODEL` (`OLLAMA_MODEL` for `ollama`), empty when absent. An empty model means the CLI's own default, auto-selection for `ollama`, and no slashdo override for `opencode` (select or configure a supported provider/model there). A saved `review-models` default (see `/do:config`) fills in the model when the token has no bracket; an explicit bracket wins.
- **`cmd[<invocation>]`** runs any harness not in the list (see `lib/local-agent-cmd.md`). The bracket is the operator's shell command, recorded verbatim as `{REVIEWER_CMD}`, which reads the review prompt on stdin and prints the verdict. It is always review-only and takes no `[<model>]` or `~effort=`; put those in the invocation. Reject a bare `cmd`, an empty or whitespace-only invocation, unbalanced brackets, or a newline in the invocation with the unknown-value abort, because the string the operator saw validated has to be the one handed to `bash -c`.
- **`@<login>`** requests a review from a user, App, or bot on the project's code host (`@octocat`, `@some-app[bot]` on GitHub; `@jane.doe`, `@project_42_bot` on GitLab): slashdo requests the review on the PR/MR, waits, and fixes what it surfaces; it never posts an approval itself. Strip the `@` into `REVIEWER_LOGIN`. The code host may not be resolved yet, so accept a login that matches either host's grammar — GitHub `^[A-Za-z0-9][A-Za-z0-9-]*(\[bot\])?$` or GitLab `^[A-Za-z0-9_]([A-Za-z0-9_.-]*[A-Za-z0-9_-])?$` — and reject any other with the unknown-value abort. The loop re-checks it against the resolved host. No model bracket.
- **Unknown value**: abort with `Unknown --review-with value: {value}. Use one of: codex, agy, claude, grok, pi, cursor, opencode, ollama, copilot, cmd[<invocation>], @<login> (each optionally suffixed ~opt, ~max=<n>, and/or ~effort=<level>).`
- **Dedupe**, keeping first-occurrence order, on the entry's identity: the normalized slug plus its `[<model>]`; the verbatim invocation for `cmd` (case- and whitespace-sensitive); the lowercased login for `@<login>`. So `gemini`/`agy` and `@Octocat`/`@octocat` collapse, while `codex[a]`/`codex[b]` stay distinct. The survivor is optional if any collapsed occurrence had `~opt`, and takes its cap and effort from the first occurrence that carried each. If anything was dropped, print `Note: deduped --review-with list to {final list}.`
- Record the ordered list as `REVIEW_AGENTS`. There is no built-in default reviewer: when `--review-with` is omitted, leave `REVIEW_AGENTS` unset so the saved-defaults step can fill it from `/do:config`; if it is still unset after that, `REVIEW_AGENTS=[]` (no external review pass; the Local Code Review gate still runs). Exactly the listed reviewers run, in order.

Parse `$ARGUMENTS` for the stop-mode flags (mutually exclusive):
- `--review-stop-on-findings` — stop the multi-reviewer loop after the first reviewer that fixed at least one finding.
- `--review-stop-on-clean` — stop after the first reviewer that reports a clean pass with zero findings.
- If neither is present, set `REVIEW_STOP_MODE=all` (default — run every listed reviewer in order).
- If both are present, abort with: `--review-stop-on-findings and --review-stop-on-clean cannot be combined`.

Parse `$ARGUMENTS` for `--review-mode <series|parallel>`:
- `series` (default, recommended) — reviewers run one at a time in list order, each reviewing against the prior reviewer's committed fixes.
- `parallel` — reviews run concurrently against one frozen baseline, then the orchestrator applies the deduped union of findings once; no reviewer sees another's fixes, and `--reviewer-applies` and the stop-modes are ignored (the loop warns).
- If omitted, leave `REVIEW_MODE` unset for now — the saved-defaults step fills it from the `review-mode` default; the built-in default is `series`.
- Any other value: abort with `--review-mode must be one of series, parallel (got: {value}).`

Parse `$ARGUMENTS` for `--reviewer-applies` (boolean):
- Record as `REVIEWER_APPLIES=true` if present, otherwise `REVIEWER_APPLIES=false` (default).
- By default the orchestrating thread applies the fixes a reviewer surfaces; with `--reviewer-applies` the reviewing CLI edits the working tree directly. It only affects the `codex` pass, the one reviewer with a verified write-isolated profile; every other local reviewer stays review-only. When `REVIEWER_APPLIES=true` and `REVIEW_AGENTS` contains `copilot` or an `@<login>` (read-only cloud reviews), print `--reviewer-applies has no effect on the copilot/@<login> passes; fixes there are always applied by the orchestrator's sub-agent` and continue; when it contains `ollama` (`ollama run` returns text and cannot edit files), print `--reviewer-applies has no effect on the ollama pass; Ollama is non-agentic, so the orchestrator always applies the fixes` and continue.

Parse `$ARGUMENTS` for `--review-iterations <n>` (host-side passes — `copilot` and `@<login>` — only):
- Record as `REVIEW_ITERATIONS`; default `1` — one review-and-fix pass per host-side reviewer (request one review, fix everything it surfaces, stop).
- A positive `n` runs at most `n` review-and-fix cycles per host-side reviewer, exiting early if a review returns 0 comments; `0` means "loop until that reviewer returns 0 comments", bounded by the same built-in ceiling of 10 rounds.
- If missing or not a non-negative integer, abort with: `--review-iterations must be a non-negative integer (got: {value}).`
- No effect on local-agent reviewers or `ollama`, whose built-in cap is 3; the per-entry `~max=<n>` suffix moves those and overrides this flag for the entry that carries it.

Every multi-reviewer-loop invocation this command makes (over the whole list, or over the sub-list the command partitions out in place of `{REVIEW_AGENTS}`) receives the resolved values as `{REVIEW_AGENTS}`, `{REVIEW_STOP_MODE}`, `{REVIEW_MODE}`, `{REVIEWER_APPLIES}`, `{REVIEW_ITERATIONS}` (the copilot / `@<login>` cycle cap), and `{REVIEW_MODELS}` — the `EFFECTIVE_REVIEW_MODELS` map the saved-defaults step resolves from `review-models` (empty when none is saved); without it a saved per-agent model is silently ignored.

## The `cmd` reviewer

`cmd[<invocation>]` is the escape hatch for a harness slashdo has no recipe for — any headless CLI, wrapper script, or remote call the operator can drive from a shell. It is prompt-driven and **always forces review-only**, regardless of `--reviewer-applies`. Everything else in the loop (prompt, verdict parsing, snapshot+revert, push, iteration, merge gate) applies unchanged.

**The contract is stdin in, stdout out — nothing else.** `{REVIEWER_CMD}` is run as `bash -c "$REVIEWER_CMD"` with `$LOCAL_PROMPT` piped to its stdin, and its stdout must be the same verdict format every other reviewer produces (`NO FINDINGS`, or `FINDING <N>:` blocks). No `MODEL_FLAG`/`EFFORT_FLAG` is built for it and there is no binary to probe (pre-flight step 3 does not apply); any model, provider, runtime, or effort selection is baked into `{REVIEWER_CMD}` (e.g. `cmd[pi --harness ollama --model llama3:70b --effort high]`). A harness that wants the prompt as a flag adapts in the invocation itself (`cmd[my-cli --prompt "$(cat)"]`, `cmd[xargs -0 my-cli --review]`, or a wrapper script).

**`{INVOCATION}` is `bash -c "$REVIEWER_CMD"` and nothing else.** Step 2's `cmd` branch pipes the prompt in front of the whole timed line (`printf '%s' "$LOCAL_PROMPT" | ${TIMEOUT_CMD[@]+"${TIMEOUT_CMD[@]}"} {INVOCATION}`). Folding the `printf ... |` into `{INVOCATION}` would leave `TIMEOUT_CMD` wrapping only the `printf`, so the reviewer runs unbounded; running the plain form gives the reviewer no stdin. With an empty `TIMEOUT_CMD` (stock macOS) the operator's own invocation must supply a bound.

**Missing executable.** A `bash -c` exit of `127` (command not found) or `126` (not executable) is the missing-binary case: record `STATUS=skipped`, not `cli-error` — the reviewer never launched, so the tree is untouched, and a hard error would trip the wrapper's short-circuit over every remaining reviewer. Every other non-zero exit is `cli-error`.

**Trust boundary.** `{REVIEWER_CMD}` is operator-authored — typed on the command line or saved in the **global** config via `/do:config` — and runs via `bash -c` with no sandboxing this loop can apply. Never populate it from untrusted input (repo content, a PR body, an issue). A per-project `.slashdo.json` is repo content — committed and editable by anyone who can land a commit — so the saved-defaults step drops a `cmd[…]` entry read from it with a warning, and `/do:config --project` refuses to store one.

**Isolation, permanently absent.** An opaque invocation's isolation is unknowable by construction, so there is no scoped profile to attempt and never will be. It always runs the tool-free fallback, backstopped only by Steps 1/3's snapshot+revert, which covers the git-tracked tree and git metadata, never a network call or an action outside the working tree. Choosing `cmd` accepts that residual risk.

**Reporting.** Log and report it as `cmd:<first whitespace-delimited token of the invocation>` (e.g. `cmd[pi --harness ollama --model llama3]` → `cmd:pi`). The label is the **only** rendering of a `cmd` entry anywhere — plan banner, dedup note, per-pass table, commit subject (`address review (cmd:pi): <summary>`), final report — never the raw invocation, which may carry a baked-in key or token. Build it by filtering the first token to `[A-Za-z0-9._/-]` and pass it as its own argv element (`git commit -m "$SUBJECT"` with the label already inside the variable), never spliced into a double-quoted shell string where `$(…)` or a backtick would expand.

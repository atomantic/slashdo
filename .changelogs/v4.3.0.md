# Release v4.3.0

Released: 2026-10-23

## Highlights

- **Keep the dependencies your project depends on.** A shared dependency allowlist protects exact packages and wildcard families from removal proposals in every audit mode, while vulnerability reporting and transitive accounting remain active.
- **Avoid duplicate issue work.** Issue claims now check every open GitHub PR body and head commit, alongside branches, assignees, and progress markers, and stop when ownership evidence cannot be verified.
- **Complete clean reviews with an approval.** PR and MR reviews now approve someone else's change after a completed review has no unresolved critical findings, with a configurable opt-out and checks that the approved commit is the one reviewed.

## Added

- Configure dependency policy globally or per project with `--depfree-allow`. Both lists are combined, support exact names and literal `*` patterns, and apply before cached decisions in default, heavy, and extreme dependency audits.
- Report policy-kept packages and matching patterns in audit summaries and dependency decision records. Removing an allowance triggers fresh classification and recomputes dependencies previously kept through that parent.
- Distribute the policy through npm and shell installers, with runtime-independent instructions for projects without Node.js.

## Fixed

- Gather complete, paginated GitHub PR and commit evidence before fresh issue claims, including claims on arbitrary branch names. Same-login assignments and `in-progress` markers remain owned by their existing run; continuation requires a verified same-run record.
- Apply review approvals only after self-review, fixes, validation, and delegated reviews finish. Drafts, self-authored changes, explicit opt-outs, and incomplete reviews cannot approve.
- Pin GitLab approvals to the reviewed SHA and withdraw this run's GitHub approval if the head moves or cannot be verified after publication. CI and other required approvers remain independent merge gates.

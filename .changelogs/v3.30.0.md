# Release v3.30.0

Released: 2026-08-16

## Highlights

- **Issues can now recommend how to run the work.** `/do:plan-task` gives each issue it files a *dispatch hint* on two independent axes — `model:light|medium|heavy` for how much capability the task needs, and `effort:low|medium|high|xhigh|max` for how much reasoning budget per step. It infers both from the code it just investigated and shows them at the approval gate, so a bad call is cheap to correct before the issue exists.
- **`/do:next` reads those hints back.** `--model` and `--effort` filter the queue to the kind of work you're in the mood for, and in `--swarm` mode each worker agent runs at the model tier its own issue asks for — so a mixed batch stops paying one flat rate per agent. (The `effort:` axis is written, filtered, and reported everywhere, but only *dispatched* on hosts whose sub-agent API exposes an effort control — which Claude Code's `Agent` tool does not, so workers there run at the session's effort.)
- **slashdo no longer hardcodes model names anywhere.** Commands that spawn sub-agents used to name Opus, Sonnet, and Haiku directly, which broke on the other CLIs slashdo installs into and went stale as model lineups churned. They now pick a tier and let whichever CLI you're running resolve it against its own models.
- **Referenced library docs resolve properly on Codex, Antigravity, and Grok.** A lib doc citing another lib left an unopenable path in the generated skill and skipped inlining the doc it pointed at.

## Issue dispatch hints

- Issues filed by slashdo can carry `model:` and `effort:` labels recommending how to run the work. The two axes are deliberately independent, and the off-diagonal combinations carry the most information: `model:light` + `effort:max` describes a mechanical change across forty call sites, where no insight is required but a silent miss is easy, while `model:heavy` + `effort:low` fits a two-line change that hinges on one good idea. This is not a size estimate.
- `/do:plan-task` infers both axes from what it found in the codebase and states them with a one-line justification at the approval gate. `--model <tier>` and `--effort <level>` override an axis outright; `--model none` suppresses one.
- Applying a hint is optional and an unlabelled issue stays fully claimable. A reflexive middle value on everything is noise that makes the deliberate hints unreadable, so the guidance is to leave an axis off rather than guess it — and `/do:replan` is explicitly barred from stamping hints onto migrated backlog items in bulk.
- If your repo already uses its own sizing taxonomy (`size/M`, story points, `complexity:*`), plan-task prefers that over introducing new labels, the same way it already prefers your existing type labels.

## Claiming work by dispatch hint

- `/do:next --model` and `--effort` restrict auto-pick to issues carrying the matching hint. A comma list is OR *within* an axis and the two axes AND *across*, so `--model light,medium --effort low` claims work that is (light or medium) and low.
- The sentinel `none` matches issues with no label on that axis — `--model light,none` reads "light work, or work nobody has tiered yet", which is the form you want on a tracker that is only partly labelled. Without it, untiered issues are filtered out; when a filter empties the queue, `/do:next` now says which filter did it instead of reporting a bare empty backlog.
- In `--swarm` mode each worker agent is configured from its own issue's labels, so a batch of mixed work no longer runs every agent at the same cost. The batch summary gained a dispatch column, which is what makes a wrong hint visible after the fact.
- The filters are advisory, not a gate: an explicit `#<num>` overrides them, an unhinted issue is always claimable, and they have no `/do:config` saved default by design — a forgotten saved narrowing is indistinguishable from an empty backlog.

## Host-neutral model selection

- `/do:better`, `/do:better-swift`, `/do:depfree`, `/do:review`, and `/do:rpr` now select sub-agent models by tier — `light`, `medium`, `heavy` — instead of naming specific models. Each host CLI resolves a tier against the models it actually has. The Quality/Balanced/Budget profiles and their behavior are unchanged; only the values they resolve to.
- This matters because slashdo installs into Claude Code, OpenCode, Antigravity, Codex, and Grok Build, and drives local Ollama models — none of which share a model namespace. A model name from one host's lineup was meaningless on the others, and went stale everywhere as lineups churned.
- A tier is named with the host's **model alias** (`opus` / `sonnet` / `haiku` on Claude Code), never a fully-qualified version ID like `claude-opus-4-8`. An alias resolves to whatever version your organization has configured, so it neither goes stale as lineups churn nor overrides a pinned deployment — which means `heavy` can name the strongest tier outright and genuinely *upgrade* the work, rather than settling for whatever model the session happened to start on. If an account lacks entitlement to that tier, the dispatch retries once inheriting the session and says so.
- A host that cannot set a per-agent model runs at the session default and says so, rather than refusing to work.

## Fixes

- Library docs that cite a sibling library — using a `./name.md` link, because the `../../lib/` form is wrong from inside the library directory — now resolve when generating skills for Codex, Antigravity, and Grok. Previously the citation survived into the generated skill as a path the user could not open, and the doc it pointed at was never added to the "Referenced libraries" section. Links to files in your own repo, like `./PLAN.md` or `./GOALS.md`, are correctly left untouched.

## Internal

- The tier vocabulary and its resolution rules live in one place (`lib/model-tiers.md`) rather than being restated per command, and the tracker labels resolve through the same file so the runtime and the label taxonomy can't drift apart.
- The audit and remediation model variables were renamed to reflect that they hold a tier rather than a model name. `/do:depfree` gained a note keeping its three senses of "tier" and "heavy" apart — model tier, dependency Tier 1/2/3, and `--heavy` removal mode are independent of each other.

# Release v3.32.0

Released: 2026-08-17

## Highlights

- **PRDs now carry evidence, not just claims.** `/do:goals --prd` (and `/do:prd`) records where each requirement came from — a passing test, a documented contract, observed behavior, or an explicit inference — and refuses to present an unsupported guess as an observed requirement.
- **Refresh no longer overwrites approved wording.** An existing PRD is treated as the baseline: stable IDs stay put, user-authored requirements are kept when current code is incomplete, and contradictions go into Risks & Open Questions instead of being silently resolved.
- **Interactive PRDs walk real boundaries.** Before writing the document, `--prd --interactive` tests the draft against concrete edge cases (validation failures, explicit refusals, ambiguous scope) so out-of-scope and MUST-NOT lines are confirmed rather than inferred.

## PRD evidence and boundaries

- Discovery now mines merged pull-request history (30–100 titles, a sample of full bodies) for demonstrated product intent, falling back to default-branch commit history when PR access is unavailable. Isolated historical changes and generic engineering practices are not treated as product requirements.
- Requirements mining keeps a private evidence ledger through synthesis: every functional, non-functional, or negative requirement needs at least one evidence note or must be labeled as an inference / open question. Conflicting signals are recorded rather than picked silently; acceptance criteria prefer the most recent verified behavior.
- Generated PRD tables gained Confidence and Evidence columns (functional, non-functional, and negative requirements), and Out of Scope is now a table with a supporting signal.
- `--refresh` compares the existing document's evidence notes against the current codebase, reports which evidence caused each change, and will not replace a user-authored requirement with a different inference just because the implementation is incomplete.

## Fixes

- A follow-up pass keeps approved refresh baselines and scope evidence intact so a later scan cannot quietly drop them.

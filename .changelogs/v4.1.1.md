# Release v4.1.1

Released: 2026-10-20

## Highlights

- **Feature work never lands on the default branch by accident.** A new feature worktree created from `origin/main` inherits `main` as its upstream. `/do:pr`, `/do:push`, the review loops and the merge gate now recognize that inherited tracking and publish the feature branch itself instead of pushing its commits to the default branch.
- **The swarm starts working immediately and stops spending reviewer tokens on health checks.** `/do:next --swarm` no longer runs a full review of a large sample diff before any worker starts. Required reviewers get zero-token checks only (installed, logged in, isolation flags present), and optional (`~opt`) reviewers aren't checked at all.
- **Local reviewers' verdicts parse reliably.** The Claude reviewer now returns schema-validated output instead of prose, grok's verdict is read from its final message instead of a transcript with narration mixed in, and every prompt-driven reviewer is told twice, including after the diff, to print nothing but its findings.
- **The grok reviewer works at every effort level.** It uses grok's real `--reasoning-effort` flag, clamps `max` to grok's top level `xhigh`, reads its prompt from a file, and runs with grok's actual read-only isolation flags.
- **Parallel agents no longer erase each other's branch tracking.** When a local reviewer finishes, slashdo checks and restores only the security-relevant git config keys, so branches other worktrees publish during a long review keep their upstreams.
- **`/do:next` correctly sees claimed issues when run with arguments.** Claude Code was substituting the command's arguments into its in-flight check, so issues already claimed elsewhere looked free.

## Fixed

- Inherited base tracking is distinguished from a real PR head before a push destination is chosen. The default branch is resolved from `origin/HEAD` with a `git remote show` fallback, and the GitLab wait-mode push is guarded the same way.
- Swarm reviewer preflight makes no model call. Required entries are checked only for the binary, the CLI's own login status (`codex login status`, `claude auth status`), recipe isolation flags, and code-host auth for PR-side reviewers; a failure still aborts before any claim. Quota, provider admission, input-size and non-verdict failures are met and classified by each worker's real review. A reviewer whose recipe allows read tools is never treated as unavailable for that.
- The Claude subprocess reviewer runs with `--output-format json --json-schema`, and its structured result is converted to the `FINDING`/`NO FINDINGS` contract before the unchanged strict parser. Error results, missing or invalid verdicts, and contradictory verdicts stay `no-verdict`; the in-process text path is untouched. The first pass checks that the CLI supports `--json-schema` and that `jq` is installed.
- The review-only prompt forbids any preamble, progress note or summary around the verdict, and the payload repeats the output contract after the diff.
- grok reviews use `--prompt-file`, `--reasoning-effort` (with `max` clamped to `xhigh`), plan mode with a read-only sandbox, no web search and no subagents, and read the final result from `streaming-messages-json`. The verdict is extracted only on a zero exit, so a CLI error still shows grok's own message, and parallel review mode now runs each reviewer's pre- and post-launch steps.
- The local CLI runner's git-metadata check compares and restores only security-relevant keys: hook paths, fsmonitor, pagers and editors, SSH commands, aliases, includes, filters, diff and merge drivers, diff and merge tool commands, credential helpers (order preserved), and remote URLs. Changes to `branch.*` and other unrelated keys are reported as concurrent activity and never reverted. The hooks-directory check is unchanged.
- Command bodies no longer contain positional `$N` tokens, which Claude Code replaces with the command's arguments. This affected `/do:next`'s in-flight matcher and claim read-back, and `/do:release`'s checkpoint helpers.

## Internal

- Contract tests cover the inherited-base push guard, the per-key metadata restore (run against a real linked worktree), the zero-token preflight, the Claude structured-verdict conversion (run against real CLI output), the grok invocation, and a lint check that rejects any `$<digit>` in a command body.

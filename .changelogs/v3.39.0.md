# Release v3.39.0

Released: 2026-09-17

## Highlights

- **Any CLI can now be a reviewer: `--review-with 'cmd[<invocation>]'`.** The fixed slug list only covered harnesses slashdo has a verified recipe for. A `cmd` entry lets you name any shell command — a wrapper script, a Pi+Ollama combination, any tool with a headless mode — that reads the review prompt on stdin and prints the standard `NO FINDINGS` / `FINDING <N>:` contract. Verdict parsing, iteration, push, and the merge gate all work unchanged.
- **`agy`, `grok`, and `cursor` actually run now.** None of the three ships a tool-restriction flag, so the old "tool-free fallback requires an enforced empty tool set" rule was unsatisfiable and every review with them silently returned no-verdict without ever invoking the CLI. They now run under the loop's working-tree snapshot-and-revert, which is real enforcement rather than a flag nobody offers.
- **A repo can no longer choose the shell command slashdo runs.** A per-project `.slashdo.json` is committed repo content, so a `cmd[...]` reviewer read from one is now dropped with a warning, and `/do:config --project` refuses to store one. Only your command line and your global config can supply a `cmd` reviewer.
- **The review-only snapshot now covers `.git` metadata.** The snapshot that justifies running unrestricted reviewers never looked inside `.git/`, so a planted hook or a `core.hooksPath` edit survived it. `.git/config` and the hooks are now hashed, compared first, and restored before any other git command runs.
- **Parallel review mode is no longer unsnapshotted.** It ran only the invocation step per reviewer, meaning tool-free reviewers had no snapshot at all. It now snapshots once before the fan-out and compares and restores once after the barrier.
- **GitLab labels use native scoped syntax.** Dispatch, severity, model, effort, and priority labels now render as GitLab's two-tone `key::value` scoped labels (one value per key), while GitHub keeps the single colon. `/do:next`'s priority sort and dispatch-hint matching build the separator from the host instead of hardcoding a colon, which would have quietly stopped matching on GitLab.

## Added

- `cmd[<invocation>]` reviewer escape hatch across the `--review-with` parser, every dispatch gate, the dedup identity rules, `lib/better-options.md`'s grammar, and the transformer's on-demand-load hint. Always review-only regardless of `--reviewer-applies`, since an opaque command's isolation can't be verified.

## Changed

- Reviewer dispatch gates now use an exclusion (`none of copilot, ollama, or @<login>`) rather than an enumerated allowlist, so a new reviewer type reaches the local-agent loop without touching six separate gates.
- `README.md`, `/do:pr`, and `/do:release` no longer claim `--reviewer-applies` reaches `agy`/`claude`/`grok`/`cursor`/`opencode`; the loop forces all of them review-only.

## Fixed

- The `cmd` timeout wrapper was scoped to `printf` instead of the reviewer command, leaving `cmd` runs unbounded.
- A `cmd` whose executable is missing is recorded as `skipped` like any other missing binary, instead of a `cli-error` that short-circuits the remaining reviewers and is never excused by `~opt`.
- Oversized prompts on an argv path degrade to `no-verdict` instead of failing exec on Linux's 128 KiB per-argument cap and surfacing as a hard error.
- The invocation table had prose instead of executable commands for `agy`/`grok`/`cursor`.
- `pi` was missing from `/do:release`'s local-agent-specific merge checks, a gap that predated `cmd`.
- The `LABEL_SEP` derivation was folded into the existing select block; adding a third fenced block silently broke the `vcs-host` contract test that asserts exactly two.

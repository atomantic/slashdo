# Release v3.40.0

Released: 2026-09-23

## Highlights

- **`/do:next` understands merge flags.** `--merge`, `--no-merge`, `--merge=<method>`, and `--merge-method` are now defined, so you can open the PR and stop for human review, or pick squash/rebase/merge. Unknown flags now abort before anything is claimed instead of being silently ignored.
- **Single-issue `/do:next` merges wait for required CI.** The merge method is resolved from your flags, saved defaults, or the repo's allowed methods, and the merge is gated on required checks, matching the swarm merge queue.
- **Your saved reviewer is respected.** When you don't pass `--review-with`, `/do:next` no longer picks a reviewer of its own. `/do:pr` applies your saved default, and the merge gate follows what actually ran.
- **`/do:next` leaves your checkout alone.** Cleanup after a merge updates the default branch without switching the branch you have checked out in the main repo, so a dirty tree can no longer strand a claim branch on the remote.
- **Leaner `/do:next` context.** Issues mode no longer loads every open issue body. GitLab-only steps load only on GitLab repos. Host detection comes from the shared library, and the issue-filing rules are split away from the setup that `/do:next` needs. Repeated rationale is collapsed into a single Conventions block.
- **Accurate cross-references.** Stale pointers left over from the library split are fixed: abandoned-claim teardown, parent-epic lookup, and the swarm's reuse of Phase 1.

## Changed

- Split the issue-mode library into a setup part (label separator, lazy label creation, dispatch hints) and a filing part (dedup, `--scan-only`, bulk spool). The `plan` label is now created only when an issue is actually filed.
- `/do:next` reads its saved defaults with a literal config read instead of pulling in the full review-config reference.
- The PLAN.md slug-format reference no longer describes another tool's branch convention.
- The `/simplify` note now says that it is the harness's built-in quality pass and is distinct from `/do:simplify`.

## Fixed

- `/do:next` no longer forwards its own merge flags to `/do:pr`, which could abort the run after implementation.
- Host detection no longer runs `gh repo view` when there is no `origin` remote, and it reports unsupported forges clearly.
- Removed dead `--auto-merge` polling guidance and the duplicated `/do:next` notes section.

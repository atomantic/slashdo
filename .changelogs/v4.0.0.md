# Release v4.0.0

Released: 2026-09-24

## Highlights

- **Issue trackers are the backlog.** PLAN.md tracking has been retired, and backlog work now flows through supported issue trackers.
- **Jira joins GitHub and GitLab Issues.** Jira project and issue keys work across planning, claiming, goal tracking, and deferred findings.
- **GitLab merge requests work across more workflows.** Release, review, discussion resolution, CI, and merge paths now support GitLab projects.
- **Code hosting and issue tracking can be configured separately.** Choose the forge for code changes and the tracker for planning work independently.
- **Review runs share a more consistent flow.** Local and hosted reviewers use common dispatch, verdict, and merge-gate rules across supported workflows.
- **Audit commands use more focused shared guidance.** The better, better-swift, and depfree workflows reuse compact phase contracts and load only the guidance their paths need.
- **Release delivery checks verify publication end to end.** The release flow checks the merged branch, tag lineage, release metadata, and package version.

## Breaking Changes

- PLAN.md mode and `--no-issues` have been removed. Backlog workflows now require issue-tracker mode; configure a supported tracker before using those workflows.

## Added

- Added Jira tracker support for issue lookup, project-scoped planning, issue claiming and transitions, goal tracking, and deferred-finding filing.
- Added GitLab merge request support to release preparation, fork PR creation, PR-mode review, review-thread resolution, and audit/release CI and merge paths.
- Added shared code-host selection and independent tracker configuration, with clear failures for unsupported or unauthenticated hosts.

## Changed

- Consolidated reviewer dispatch, local CLI execution, GitHub and GitLab review handling, and merge gates into shared workflow contracts.
- Reworked the better and better-swift command guidance into smaller shared phases, reducing default context while preserving their validation and review gates.
- Updated command and user documentation to describe supported code hosts and trackers and the issue-only backlog model.

## Fixed

- Tightened tracker and host preflight behavior so credentials cannot silently select a different code host and unsupported hosts fail before work begins.
- Improved GitLab API handling, issue-key routing, merge-request review state, and release checkpoint verification.
- Corrected reviewer dispatch, error classification, and release CI/tag checks across the command workflows.
- Kept tracker and review workflows complete under pagination and concurrent claims, and passed generated text safely through issue and review commands.
- Prevented repeated scans from overwriting reports, limited replan commits to run-owned files, and preserved open PR branches after unclean swarm recomputes.
- Corrected iOS simulator destination parsing and made Ollama review include paths containing spaces.

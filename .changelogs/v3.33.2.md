# Release v3.33.2

Released: 2026-08-23

## Highlights

- **Worktree-based merges no longer fail after a successful merge.** `/do:pr` and `/do:next` stopped passing `--delete-branch` to `gh pr merge` when running inside a linked worktree — git refuses the local branch delete there, so the whole merge step reported failure on work that had actually landed. The remote branch is now deleted in a separate, self-contained step.
- **Merge queues no longer lose work.** `gh pr merge` exits zero on a merge-queue repo while the PR is still only *queued*. Every downstream action that used to trust that exit code — deleting the head branch (which auto-closes the PR), closing the tracking issue, tearing down the worktree — is now gated on reading the PR state back as `MERGED`.
- **Large `--issues` audits keep their findings intact.** `/do:better --issues` on a big codebase used to pull every finding's full body through the orchestrator twice, truncating evidence and dropping tail findings as the audit grew. Findings are now spooled to disk and filed by per-category agents that move bytes rather than rewrite them.

## Fixed

- Audit agents spooling findings across more than one call now append after the first write — a second `cat >` would have truncated everything already spooled, the exact tail-dropping the spool path exists to prevent.
- Issue-mode remediation workers are told to read each finding's full body off the spool. `--issues` does not change what a run does, but the orchestrator now holds only index lines, so a `{FINDINGS}` block built from those alone handed the worker a one-line title with no evidence and no suggested fix.
- The small-run (~20 or fewer) inline filing path is reconciled with the spool: it lifts each block verbatim into a `--body-file` rather than being blocked by a "never opens a spool file" rule that left it with no body to file.
- `/do:next` Phase 7's new merged-PR gate is scoped to runs that actually opened a PR. A Phase 2 race hard-stop, a Phase 3 skip, or a Phase 3.5 reject has no PR to read back, and a literal reading skipped the abandoned-claim teardown — stranding the very claim branch the same phase added verification for.
- `/do:pr`'s remote delete requires a non-empty upstream ref before running: with an empty one the push fails while `ls-remote` returns 2, so it reported the benign "already gone" for a delete that never happened.
- `/do:pr` and `/do:next` detect a linked worktree with a probe that works on older git (`--path-format=absolute` is git ≥ 2.31; when the flag was rejected both substitutions came back empty and the probe answered "not a worktree", restoring the exact breakage it exists to prevent).
- The worktree probe and the remote-branch delete are written as self-contained blocks that print their result — a snippet that only assigned a shell variable was inert by the next step.
- The remote delete falls back to `git ls-remote` and distinguishes exit code 2 ("no such ref" — already gone, success) from 128 (transport/auth failure — a real error), instead of reporting every failure as "already gone".
- `/do:next` Phase 7 reads the PR state back before running any of its cleanup, so a queued-but-unmerged PR keeps its worktree and its tracking issue stays open.
- `/do:next`'s abandoned-claim retract is verified to have landed — a swallowed failure stranded a phantom claim branch that Phase 1 honoured forever.
- The swarm path deletes the head branch and closes the issue only on a `MERGED` read-back, using the branch name the worker actually returned.

## Changed

- Audit agents in `--issues` mode spool ready-to-file issue bodies to a per-run directory and return only a compact index line (`id | severity | category | file:line | title`). Cross-agent dedup and ranking still run in the orchestrator — overlapping audit agents are a design feature, so agents filing their own findings would file duplicates. The spooled path is gated at ~20 issues, so the smaller consumers (`/do:review`, `/do:rpr`, `/do:depfree`) keep the inline path.
- `/do:pr`'s pre-PR sync documents that `git fetch origin d:d` fails inside a linked worktree (git's refusal is repo-wide) and gives the remote-tracking fallback.

## Tests

- New `test/command-structure.test.js` asserts no command file's front-matter keys reappear after the block closes — the signature of a chunk of a file being spliced into itself by a careless bulk edit, which nothing else in the suite would catch.
- New `test/issue-spool-contract.test.js` pins the bulk-filing contracts: carrying the printed `SPOOL_DIR` rather than re-deriving it, keeping it in both audit commands' compaction-survival lists, the append rule, bodies never passing through the orchestrator, errored ids never counted as filed, and the one-filer-per-category fan-out with its rate-limit retry.
- New `test/worktree-merge-contract.test.js` pins the worktree-safe merge contracts: the `--delete-branch` gate, the config-derived (not hardcoded-`origin`) remote delete, the `MERGED` read-back on both `/do:pr` and the swarm path, the non-inverted delete status, and the skipped default-branch sync inside a linked worktree.
